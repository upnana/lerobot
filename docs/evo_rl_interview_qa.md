# Evo-RL 双臂实验 · 面试可能问答

> 项目：SO101 双臂 · Evo-RL ACP（value → advantage → SmolVLA）· 叠碗 + 口红/纸巾  
> 配套笔记：`evo_rl_study_job_note_jul2026.md`，`evo_rl_bowls_tray_v3_day_note_jul29.md`

---

## 0. 开场（30–45 秒）

**Q：介绍一下你做的这个项目。**  
**A：** 我在双臂 SO101 上跑通了 Evo-RL / ACP 流水线：人机协同采集 → `pistar06` value → 逐帧 advantage / ACP 标签 → SmolVLA 条件 BC → 真机评测。任务从「零食+叠碗」换成「叠碗+口红/纸巾」。当前真机：**叠碗顺序基本能完成**，卡在后半口红和纸巾。做了 value 假进度诊断和两轮 HITL（+81、+56），数据扩到 287 条。核心不是刷榜 SR，而是把长程操作里的失败模式定位清楚。

---

## 1. 任务与数据

**Q：做了几轮实验？每轮多少数据？**  
**A：**  
- 前序零食+叠碗：约 69→201，因 **缺全视野相机** 基本没做出来（不算口红任务第 ① 轮）。  
- 口红任务 ①：遥操作 **150**（采集含全视野，训练 3 相机）。  
- ②：HITL **+81** → **231**（v2）。  
- ③：HITL **+56** → **287**（v3）。  
累计 HITL 纠错 **137** 条。

**Q：为什么换任务 / 为什么加全视野？**  
**A：** 零食任务 hold，复盘是观测不够：只有腕部/局部视角，桌面全局状态不清。新任务采集加了全视野顶视；训练时对齐 SmolVLA 原生 3 槽，去掉全视野只留 top-right + 双腕，避免混分辨率和 4 相机负担。

**Q：为什么训练不用全视野那路？**  
**A：** 采集保留全视野方便人看和质检；训练上 SmolVLA 默认 3 视觉槽，4 路还要改结构/显存。实证上 3 路（场景顶视+双腕）更匹配基座，工程上也更稳。

## 2. 方法：Value / ACP / Policy

**Q：ACP 是什么？是在线 RL 吗？**  
**A：** 不是在线 PPO。流程是：用 episode 成败构造 value 目标 → 离线算 n-step advantage → 最高约 30% 标成 positive → 策略 BC 时条件文本 `Advantage: positive/negative`（训练 dropout）。部署时常 **不喂 positive**（`acp_none`），因为开局硬喂 positive 会更僵。 详见 `docs/evo_rl_acp_tag_ab_aug01.md`（v2/v3 × tag A/B + 视频）。

**Q：Value 学的是什么？**  
**A：** `pistar06` 学 \(V(s)\)，近似「离成功还有多远」，目标压到约 \([-1,0]\)，越高越接近成功。不是逐步手标 reward。

**Q：Advantage 怎么算？**  
**A：** \(A_t = \sum_{k=0}^{n-1} r_{t+k} + V_{t+n}\mathbf{1}_{\text{同 episode}} - V_t\)（n 如 50）。用 \(V\) 离线算，再阈值 ACP 标签。

**Q：为什么部署默认不用 Advantage: positive？**  
**A：** 高 advantage 帧常在 episode 后段。t=0 就喂 positive，像「已经快做完」→ 更 hold。无 tag 更接近整段遥操作分布，真机更敢动。

## 3. 真机结果与诊断

**Q：成功率多少？**  
**A：** 没有 N≥20 的严格闭环整任务 SR。按子任务说：**叠碗基本能完成**；口红/纸巾做不完整。数据里的 success% 是 **demo 标注率**，不是 policy SR。

**Q：那怎么证明模型有用？**  
**A：** 分阶段能力 + 对照 + 诊断：中期 ckpt（约 80–120k）明显好于早期 hold 和后期再 hold；value overlay 与视频对齐发现口红假进度；HITL 后行为变慢可用 v2/v3 同配置 A/B 解释。这是系统与失败模式研究，下一步再补正式 SR 表。

**Q：Value 假进度是什么？**  
**A：** 口红没抓住时 \(V\) 仍从约 -0.36 升到 -0.17。模型把「靠近/伸爪」当成进度，对 grasp success 不敏感。所以曲线好看 ≠ 子任务成功；要用视频+夹爪+残差对齐验证。

**Q：为什么后期 checkpoint 会 hold？**  
**A：** 长程 demo 大量帧是微调/停顿；多训后 BC 偏向「输出≈当前关节」。中期还记得大动作，后期被静态帧洗掉。所以评测盯 **80–120k 甜区**，不迷信 `last`。离线 loss 仍降也不能代表真机更好。

**Q：HITL 之后为什么变慢？**  
**A：** HITL 含犹豫、慢对齐、反复试抓；BC 学到慢速 prior。不是简单「数据多了」，是 **风格污染**。用同 preset、同甜区 ckpt 做 v2 vs v3 对照验证。

## 4. 工程与系统

**Q：硬件平台？**  
**A：** 双臂 SO101，12-DoF，约 30 Hz 关节位置；2×3090 DDP；conda `evo-rl`。

**Q：Latency 是什么？你测了吗？**  
**A：** Latency = 延迟。分：模型前向 ms、控制周期（30 Hz≈33 ms）、端到端感知–执行、任务完成时间。还没做前向 mean/P50/P95 表；控制按 30 Hz 跑。

**Q：P50 / P95 是什么？**  
**A：** 多次推理耗时排序后：P50=中位数（典型），P95=最慢 5% 的门槛（尾部卡顿），mean=平均（易被尖刺拉高）。

**Q：遇到过什么工程坑？**  
**A：** leader 电压/掉包打断 HITL；磁盘满导致 policy 存盘失败（从 10k resume）；value 视频 AV1 平台播不了要转 H.264；校准 mismatch 用已有文件 Enter 继续。

## 5. 方法选择与反思

**Q：为什么用 BC+ACP 而不是在线 RL？**  
**A：** 真机在线 RL 样本贵、不安全。先把离线 advantage 条件 BC 跑通，用 value 重加权「好地段」，再迭代数据。适合资源有限的双臂台架。

**Q：若重新做，你会改什么？**  
**A：**  
1. 评测协议一开始就定：分阶段 SR + N 次重复 + latency P50/P95。  
2. HITL 纠错要干脆，过滤极慢段。  
3. 对口红抓取加失败近例，压 value 虚高。  
4. 少堆已会的叠碗，集中补后半精细操作。  
5. 部署继续扫中期 ckpt，固定 `acp_none` 作主 baseline。

**Q：最大 takeaway？**  
**A：** 离线 loss ≠ 真机成功；value 曲线 ≠ 子任务完成；HITL 能纠错也能污染速度；长程双臂要 **分阶段评估 + 数据风格管理**。
